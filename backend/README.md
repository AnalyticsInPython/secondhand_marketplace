# Backend — Columbia Market API

FastAPI + SQLAlchemy, with the analysis layer in pandas. Behaviour is specified
in [`../docs/UX_SPEC.md`](../docs/UX_SPEC.md) as amended by
[`../docs/DECISIONS.md`](../docs/DECISIONS.md); the shape of the system is in
[`../docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md) and every endpoint in
[`../docs/API.md`](../docs/API.md). This README only covers running it.

## Run it

```bash
cd backend
uv venv --python 3.12 .venv && source .venv/bin/activate   # or: python3.12 -m venv .venv
uv pip install -r requirements.txt                          # or: pip install -r requirements.txt
cp .env.example .env

python -m scripts.seed --reset --demo-email you@columbia.edu    # loads ../data/*.csv
uvicorn app.main:app --reload --port 8000
```

The corpus is Kobe's, generated by `../seed/` into `../data/` (see
`../docs/mock_data_spec.md`). The loader skips the generator's external tier,
which the schema no longer has, and says how many rows it dropped. Add
`--limit 200` for a small, fast database. The listing photos are not committed;
run `python3 scripts/fetch_photos.py` from the repo root once, or
`scripts/make_photos.py` for offline gradients.

API docs: http://localhost:8000/docs. Or, from the repo root, `./dev.sh` does
all of this and starts the frontend too.

There is no password anywhere. With the defaults (`EMAIL_BACKEND=console`,
`EMAIL_DEV_MODE=true`) the sign-in link is printed to the console **and**
returned in the API response, so the sign-in screen shows it as a clickable
link. To receive it in a real Columbia inbox, set `EMAIL_BACKEND=resend` with a
`RESEND_API_KEY`, or `EMAIL_BACKEND=smtp` with your relay's details.

## Tests

```bash
pytest -q          # 61 tests, throwaway SQLite, no network
```

`tests/test_disclosure.py` is the one test the build spec says must exist: no
response to member B ever contains an attribute of member A that B does not
share.

## The analysis

```bash
python -m app.analytics.questions
```

Prints every research question. `app/analytics/frames.py` loads the tables
into pandas; a notebook can call `load()` and get the same DataFrames.

## Four things that are easy to break

1. **`services/badges.py` is the product.** An attribute that does not match is
   absent from the payload — not `false`, not `null`. If a seller's raw
   nationality or school ever reaches the client, the disclosure rule is broken
   regardless of what the UI renders. `tests/test_disclosure.py` guards it.
2. **Facet counts are live.** Each count is "what you would get if you applied
   this one filter, with everything else still on". They are meant to move.
   Caching them into static numbers removes the only honest signal the user has
   about the trust-versus-selection trade. The feed and the facets share one
   `where_clauses()`; keep it that way.
3. **`phone` is nullable and that is a feature.** A user with no number gets a
   single full-width Email button, not a disabled Text button. The seed data
   leaves ~30% of users without one so this path is always exercised.
4. **Photos are owned.** `POST /listings` only accepts URLs that came back from
   this member's own `POST /photos`. Do not relax that to "any URL" — it is
   what keeps hot-linked and other people's pictures out.

## Database

SQLite by default. Moving to Postgres is a `DATABASE_URL` change and nothing
else — no vendor-specific SQL is used anywhere.

`create_all()` runs at startup, which is fine while the schema is still moving;
`python -m scripts.seed --reset` drops and recreates every table. Introduce
Alembic before the schema stabilises.
